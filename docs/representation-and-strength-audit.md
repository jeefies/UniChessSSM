## 1. 表征健康度：E 没有坍缩

### 1.1 方法

`BoardEncoderE`（`model/e.py`）把 785 维局面特征映射到 512 维 `x_t`：

```
piece_emb(13×256) + pos_emb(64×256) + w_g(17→256) → 共享 Transformer×2 → 单查询 cross-attn → 512
```

"没坍缩到常数"是弱标准。用四个判别性指标：

1. **每格棋子身份的线性探针**（64 × 13 类，岭回归 one-vs-rest + argmax）——棋类最核心的物理量
2. **有效秩**（奇异值熵参与率 `exp(−Σ pᵢ log pᵢ)`）
3. **第 1 主成分方差占比**——有没有单一方向垄断
4. **死维**（方差 < 1e-8 的维度数）

### 1.2 结果（gen33 / gen50，5500 个真实自对弈局面）

| 指标 | gen33 | gen50 | 坍缩线 |
|---|---|---|---|
| piece_emb 行间余弦 | 0.0033 | 0.0033 | >0.5 |
| piece_emb 有效秩 | 12.90/13 | 12.90/13 | <4 |
| pos_emb 行间余弦 | 0.0011 | 0.0011 | >0.6 |
| pos_emb 有效秩 | 61.92/64 | 61.92/64 | <16 |
| **x_t 两两余弦** | 0.1455 | 0.1461 | >0.7 |
| x_t 有效秩 | 149.4 | 149.5 | 跌 |
| x_t 第 1 主成分 | 8.2% | 7.8% | 垄断 |
| 一步灵敏度 | 0.7412 | 0.7433 | >0.999 |
| 死格 | 0/64 | 0/64 | >0 |

piece_emb 13 个棋子向量两两余弦只有 0.003、有效秩 12.90/13——车和马映射到近乎正交的方向。
512 维里没有一个死维（最小方差 0.41，与均值 0.69 同量级）。

### 1.3 一个重要的副发现：E 在功能上已经冻结

权重代际差异（max abs diff，相对 gen33）：

| 参数组 | gen44 | gen45 | gen50 |
|---|---|---|---|
| piece_emb | 3.4e-3 | 7.1e-3 | 1.2e-2 |
| pos_emb | 4.3e-3 | 8.5e-3 | 1.4e-2 |
| w_g | 2.8e-3 | 4.0e-3 | 5.5e-3 |
| block.attn | 2.1e-3 | 3.5e-3 | 5.2e-3 |
| w_proj | 1.4e-3 | 2.2e-3 | 2.5e-3 |

piece_emb 行范数约 13，所以最大变化 1.2e-2 只相当于 **0.1% 的相对漂移**。配置核查：单一
optimizer、`lr 2.5e-05`、**没有参数组、没有冻结**。所以 E 确实在训，只是 lr 太小 + 处在极平坦
区域，权重动但功能不动——这也解释了为什么四项指标跨代 identical 到小数点后 3~4 位。

**对棋类这是理想状态**：棋类是完全可观测的确定性马尔可夫博弈，$B_{t+1}$ 由 $(B_t, a_t)$ 唯一
决定，输入本身就是最小充分统计量，不需要像素世界那种"抽象掉无关细节"的能力。E 收敛成近乎
无损、之后不再漂移的编码器，意味着动力学学习有一个固定的状态空间，没有 LeWM 那种
encoder-predictor 端到端共适应引入的非平稳性。

留白：如果哪天碰上平台期，"给 E 单独放大学习率" 是可试方向。现在这套探针可以直接当回归
测试用（脚本 `~/UniChess/tmp_collapse.py`），探针准确率掉超 1 个百分点就报警。

## 2. 世界模型的真实状态是 h_t，不是 x_t

### 2.1 动机

动力学支路的输入是 `g(h_{t-1}, emb_a(a_t))`（`model/g.py`），**不是 x_t**。所以 x_t 无损只能
说明编码器合格；h_t 是否同样保留局面信息、还是被 Mamba 主干为了 policy/value 方便重新混合/
压缩过，是另一个问题——对世界模型来说这才是要害。

### 2.2 方法

同一套线性探针打 h_t，与 x_t 对照。数据用 200 局真实自对弈（20,951 步），
`h = trunk(x + cond)`，训练/测试 3000/17951 切分。

### 2.3 【踩坑】漏加 cond，第一版结果全错

`model/model.py:120` 是：

```python
x = self.encode(batch.features)
cond = self._cond_expand(batch, x.shape[:2] + (x.shape[-1],))
h = self.trunk(x + cond)          # ← 主干输入是 x **加上** 条件嵌入
```

第一版脚本写成 `h = model.trunk(x)`，漏了 `cond`。后果：

- h_t 探针从 93.1% 掉到 89.7%（虚低 3.4 个点）
- **动力学支路收到分布外输入**，`dyn_rel_err` 从 0.19 虚高到 **2.4**（10 倍）

发现过程：训练日志里 `selfplay_dyn_rel_err` 是 0.19，而我测出 2.4。做了对照实验
（gen50 在自己的训练数据 vs 较早的代）排除了分布偏移，最后对账日志键名（带 `selfplay_` 前缀，
直接 grep `dyn_rel_err` 找不到）才发现口径不一致，顺带读出 cond 这一行。

**教训**：任何对中间层的测量，先把前向公式逐行对一遍。这次是靠"训练日志对账"抓出来的——
**每个诊断量都应该有一个训练侧的同名锚点**，否则错了不知道。

### 2.4 修正后的结果（gen33 / gen50）

| | x_t（E 输出） | **h_t（主干输出）** |
|---|---|---|
| 每格棋子（线性探针） | 96.82% | **93.06–93.14%** |
| 基线 | 72.42% | 72.42% |
| 行棋方 | 100% | 100% |
| 半步时钟 R² | 0.506 / 0.510 | 0.282 / 0.289 |
| 回合数 R² | 0.921 / 0.922 | 0.889 |
| 有效秩 | 168.2 / 168.3 | **350.0 / 355.5** |
| 第 1 主成分 | 8.8% / 9.1% | 13.4% |

**h_t 仍能线性解出 93.1% 的棋盘**，距基线 20.7 个百分点。主干让渡了一些棋盘精度（−3.7），
但换来有效秩翻倍（168→355）——它在把容量分给历史上下文。对世界模型是好消息：动力学支路踩在
一个**棋盘仍强线性可读**的状态上，不是有损状态。

衰退不均：半步时钟掉得厉害（0.51→0.28），回合数基本保住（0.92→0.89）。

### 2.5 探针容量分解：未决

要区分"x_t 停在 96.8% 是探针容量不够"还是"信息真丢"，按 LeWM 做法线性/MLP 各跑一份：

| 探针 | 准确率 |
|---|---|
| 线性（ridge one-vs-rest） | **96.82%** |
| MLP（hidden 512，600 epochs，AdamW+cosine） | 94.17% |

**MLP 反低于线性 2.66 个百分点。** 这不符合"MLP 必然 dominate 线性"的常理，所以我的 MLP
大概率还没训到位，**这个问题当前实现回答不了**，如实记录。

但有一点是确定的：**线性探针拿到 96.82% 本身就说明棋盘信息在 x_t 里是线性可读的**，
"非线性混合编码"这个解释已经被削弱。剩下 3.2% 是 genuinely lost 还是需要更强探针，待后续。

## 3. 动力学支路与 VoE（违反预期）

### 3.1 口径

`model/g.py` + `losses.dyn_loss`：

```
u_t   = g([RMSNorm(h_{t-1}); emb_a(a_t)])     # MLP 1024→1024→512
Δ̂_t   = predictor(u_t)                        # 512→512 两层 MLP
L_dyn = mean_t (1/d)·‖Δ̂_t − sg(x_t − x_{t-1})‖²
dyn_rel_err = ‖Δ̂−Δ‖² / ‖Δ‖²                  # 预测 Δ=0 的基线是 1.0
```

注意 `actions[t]` 配 `h[t]` 预测 `x[t+1] − x[t]`（§5.6 规格；Stage A 曾用 `actions[:, 1:]`，
从 Stage A 续训时语义会变，前若干步要观察 `dyn_rel_err` 跳变）。

### 3.2 结果（修正 cond 后，gen_0050 自对弈数据）

| | gen33 | gen50 |
|---|---|---|
| dyn_rel_err（合法转移） | **0.1947** | **0.1538** |
| VoE-A 瞬移 spike | **3.17×** | **3.94×** |
| VoE-B 非法着法比值 | 1.14 | 1.18 |

**dyn_rel_err 0.19 与训练日志 `selfplay_dyn_rel_err: 0.1898` 对上**，测量管线自此可信。

### 3.3 VoE-A（瞬移扰动）——有效，是标志性评测

把 `B_t` 里某个棋子瞬移到别的格（构造物理上不可能的结果），看 `‖Δ̂ − Δ'‖²` 是否相对合法转移
spike。gen33 3.17×、gen50 3.94×。

这说明模型对合法转移预测的是一个**特定**的 Δ，不是"局面会变"这种泛泛先验——正是 LeWM 式
VoE 要的性质。而且 gen50 比 gen33 更尖锐，动力学支路在变好。

### 3.4 VoE-B（非法着法）——基本无信息量

给同一局面配非法动作，看 `Δ̂_非法` 离合法 Δ 流形多远。比值只有 1.14 / 1.18。

原因是**合法 Δ 流形太宽**：一个局面 ~30 个合法着法的 Δ 铺开很大，任意向量落进去距离都差不多。
这个测试设计上就偏弱，不建议作为标志性评测——用 VoE-A。

### 4.6 gen33 的晋级未能复现

两种解释：晋级估计虚高（220 局 CI 宽到 0~90），或新旧开局库口径不同（晋级用 200 条旧库，
本次用 4000 条新库）。**倾向前者**——这正是当初把 Arena 从 500 提到 1200 局要堵的漏洞。

**行动意义**：门禁已改、库已换，这类窄样本晋级风险大幅降低，但历史上已发生的晋升
（gen33）不会自动纠正。如果想要一条干净的谱系，可以考虑用当前口径重测历史霸主并据此
重新排位。

### 4.7 口径保留

本次是新开局库下的绝对量，和历史晋级数字不可直接比较。gen44/45/50 之间的差距
（−6.5 / −24.8）也和它们当年晋级的幅度（+30.1 / +22.3）对不上——**同源效应**（候选就是在
霸主数据上训的）会让直接对打系统性偏保守。参照法（用非数据生成模型的第三方做尺子）
量到的差距更大，见 `value-target-experiments.md` 的专打霸主检验一节。

## 5. 绝对强度对标 Stockfish

### 5.1 设置

SF 适配层 `Server/models/SF/engine.py`（六方法契约，不走 `KIT_FACTORY`，走
`Kit.serving:game_engine_player_factory`）。二进制已装（`Server/tools/stockfish`，103MB）。
搜索预算 `depth > nodes > movetime_ms` 三选一。计时校准（20 核、8 worker）：限力档
（1 秒/步）200 局 ≈ 15 分，depth12 ≈ 36 秒，depth18 ≈ 5 分。

两类档位分工：**限力档**（`uci_elo`）名义 Elo 已知，用来夹逼 SSM 的绝对强度；
**固定深度档**与机器速度无关、可复现，适合长期跟踪。

### 5.2 结果

| SSM | SF 档 | 得分率 | Elo | CI |
|---|---|---|---|---|
| gen50 | elo_1500 | 28.50% | −159.8 | [−213.9, −112.1] |
| gen50 | elo_2000 | 8.50% | −412.8 | [−502.9, −350.1] |
| gen50 | elo_2500 | 8.50% | −412.8 | [−495.0, −354.0] |
| gen50 | depth12 | 2.25% | −655.2 | [−872.3, −559.2] |
| gen50 | depth18 | 1.25% | −759.1 | [−inf, −634.0] |
| gen33 | elo_2000 | 9.75% | −386.6 | [−472.8, −325.2] |

**夹逼失败：连最弱的 SF 档都打不过。** gen50 对 SF elo_1500 只有 28.5%，Elo 差 −160
（CI [−214, −112]，不含 0）。按 SF 的 UCI_Elo 标尺，gen50 在 64 sims 下约 **1340**。

### 5.3 四个必须说明的问题

1. **这是 64 sims 口径，不是生产强度。** 循环 Arena 用 64 sims（确定性对局口径），Server 的
   `champion` 预设用 **256 sims**。所以 1340 是"循环内淘汰赛 setting 下的绝对强度"，
   不是网站上下棋的强度。

2. **elo_2000 与 elo_2500 得分率完全相同（8.50% / −412.8）**，不正常。要么 SF 19 的
   `UCI_Elo` 在高档位不区分（1500 档明显有削弱效果，2000/2500 没有差别），要么测试有系统性
   偏差。**待复核**（§5.4）。

3. **gen33 vs gen50 在 SF 标尺上没复现 round-robin 的结论。** gen33 对 elo_2000 是 9.75%
   （−386.6），gen50 是 8.50%（−412.8）——gen33 反而略好 26 Elo。但两边 CI 都有 ±74 宽，
   **这个测试没有功效分辨 40 Elo 的差距**。采信 round-robin，SF 这一格只能算"不矛盾"。

4. **开局库形态差异**：新库 4000 条是 UCI 格式、随机合法 6–12 ply；旧库 200 条是 SAN 格式、
   curated 开局。`OpeningBook.parse_line` 两者都吃。新库本身质量没问题
   （|子力差| 中位 0、86.4% 为零、≥3 仅 2.5%、≥5 为 0%）。

### 5.4 待复核

## 6. 方法论沉淀

1. **每个诊断量都要有训练侧同名锚点。** 这次 `dyn_rel_err` 虚高 10 倍是靠"训练日志对账"
   抓出来的。没有锚点的测量，错了不知道。
2. **对中间层测量前，先把前向公式逐行对一遍。** cond bug 就是这么漏的。
3. **"没坍缩到常数"是弱标准**，用线性探针 + 有效秩 + 主成分占比 + 死维四件套。
4. **两两比较要用同一批开局。** 全对打所有对共用同一 seed 同一本库，否则开局差异会混进 Elo。
5. **备份文件名会骗人。** `champion_genX_backup.pt` 装的是被 gen X+1 打败的霸主，不是 gen X。
6. **MLP 探针不一定赢得过线性探针。** 这次 MLP（512 隐层 / 600 epochs）反而低 2.66 个点，
   容量分解的结论因此未决——报"未决"比报一个假结论诚实。
7. **VoE 要选对变体。** 瞬移扰动（改目标）spike 3~4 倍，有效；非法着法（改动作）比值只有
   1.1，因为合法 Δ 流形太宽，设计上就偏弱。
