### 2.2 `tools/ssm_gumbel_arena.py:295-314` — 换色局胜者归属错误

**问题：** `_aggregate_results` 在 `arena_result` 已经是 A 视角（0=A 胜, 2=B 胜）的情况下，又用 `white_ckpt_side`/`black_ckpt_side` 做了一次白/黑方映射。当 A 执黑获胜时（`arena_result=0`, `white_ckpt_side="B"`），胜利被错误计入 B；对称地，A 执白落败时（`arena_result=2`, `black_ckpt_side="B"`），失败被错误计入 A。**之前的 32 局 A/B 结论（Stage A 12 / Round 2 20）因此不可信，需重跑。**

```python
# 修复前（错误：双重映射）
for gd in games_log:
    if gd["arena_result"] == 0:
        if gd["white_ckpt_side"] == "A":   # arena_result 已是 A 视角，不应再查 side
            wins_a += 1
        else:
            wins_b += 1
    elif gd["arena_result"] == 2:
        if gd["black_ckpt_side"] == "A":   # 同上错误

        else:
            wins_b += 1
```

**修复：** 直接用 `arena_result` 计数，去掉 side 分支。

```python
# 修复后
for gd in games_log:
    if gd["arena_result"] == 0:
        wins_a += 1
    elif gd["arena_result"] == 2:
        wins_b += 1
    else:
        draws += 1
```

**影响范围：** 所有 arena 结果（A/B、换代判定）均受影响。

## 3. WARNING 修复（5 项）

### 3.1 `tools/ssm_gumbel_selfplay.py:204-206, 250-252` — occurrence 编码时机不一致

**问题：** 根节点路径 (`_play_ply`) 使用 `encode(board, occurrence=occ)` 其中 `occ` 是** increment 前的计数**（首次访问传 0）；搜索展开路径 (`_expand_gen`) 使用 `encode(board, occ.get(key, 0))` 其中 occ 是** increment 后的计数**（首次访问传 1）。`features.py` 将 `occurrence=0` 映射为 `is1=0, is2=0`，`occurrence=1` 映射为 `is1=1, is2=0`。同一局面经过根节点和经过搜索树展开时，得到的重复特征位不同，违反 E 缓存键一致性要求（§2.3）。

**修复：** 将 `_expand_gen` 中路径上的 encode 移到 increment 之前，与根节点行为对齐。

```python
# 修复前（expand 路径）
occ[key] = occ.get(key, 0) + 1
feats, tc_val, elo_std, _ = encode_board(board, occ.get(_board_key(board), 0))  # 传 1

# 修复后
feats, tc_val, elo_std, _ = encode_board(board, occ.get(_board_key(board), 0))   # 先 encode
_, _, _, _, cache = yield (feats, int(tc_val), float(elo_std), color, cache)
occ[key] = occ.get(key, 0) + 1                                                    # 后 increment
```

### 3.5 `stateseq/model.py:111` — dyn 索引语义变更的 checkpoint 兼容性注释

**问题：** `batch.actions[:, :-1]` 替换了 `batch.actions[:, 1:]`。新索引正确对齐 `h_{t-1}` 与 `a_{t-1}` 预测 `x_t - x_{t-1}`（规格 §5.6），但 Stage A checkpoint 是在旧索引语义下训练的。从 Stage A checkpoint 续训时，dyn 损失定义发生静默语义变化。

```python
# 从 Stage A checkpoint 续训时，dyn 损失定义发生语义变化，前若干步需观察 dyn_rel_err 跳变。
```
