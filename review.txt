**不考虑调试输出，这份代码也有多处独立错误，不是只改一个地方就能解决。** 其中有些会导致 WA，有些会直接导致无限递归、段错误。

我按你的“莫队 + 树链剖分 + 线段树维护连通块”思路做了修正，并进行了暴力对拍。下面按**原文件行号**解释。

## 1. 第 90 行：建树时把赋值写成了比较

原代码：

```cpp
tag[x == ++idx] = 0;
```

这里的 `x == ++idx` 是比较表达式，结果是 `0` 或 `1`，**不会把新节点编号赋给 `x`**。因此，根和左右儿子的节点编号根本没有正确建立。

应改为：

```cpp
x = ++idx;
tag[x] = 0;
```

或者原本大概想写的：

```cpp
tag[x = ++idx] = 0;
```

这是最先需要修复的问题。

## 2. 第 128 行：`updcol` 递归到左儿子时，区间没有缩小

原代码：

```cpp
if (pos <= mid)
    updcol(ls[x], l, r, pos);
```

应为：

```cpp
if (pos <= mid)
    updcol(ls[x], l, mid, pos);
```

你传入的仍然是 `[l, r]`。只要进入这个分支，之后 `mid` 和判断条件都不变，会不断向左递归，最终栈溢出，而不是正常走到叶子。

另外，这个函数最后调用的是同时维护 `sum`、`mx`、`col` 的 `push_up`。为保持懒标记与区间聚合值一致，修正版也在向下递归前补了 `push_down(x, l, r)`。

## 3. 第 149 行：找第 `k` 个零，分支条件应为 `>=`，不是 `==`

你的 `find(x)` 先计算链上前缀中有多少个零，再通过 `binary` 找对应的零位置。按这个维护方式，`binary` 实际上是在找**整条链中的第 `k` 个零**。

原代码：

```cpp
if (mid - l + 1 - col[ls[x]] == k)
    return binary(ls[x], l, mid, k);
```

设左子树中零的数量为 `cnt`，正确判断应该是：

```cpp
int cnt = mid - l + 1 - col[ls[x]];

if (k <= cnt)
    return binary(ls[x], l, mid, k);

return binary(rs[x], mid + 1, r, k - cnt);
```

例如，左边有三个零，要找第二个零，显然也应该进入左边；你的 `==` 却会进入右边，并把 `k` 减成负数。

## 4. 第 228 行：`del()` 最后翻转的不是被删除的边

这里是一个比较隐蔽的变量覆盖问题。

函数开头：

```cpp
int x = E[p].u;
```

此时 `x` 是边 `p` 较深的端点。但后面你执行了：

```cpp
x = fa[x];

while (top[x] != top[y]) {
    // ...
    x = fa[top[x]];
}
```

到最后：

```cpp
T.updcol(rt[top[x]], dfn[top[x]], lst[top[x]], dfn[x]);
```

**这个 `x` 已经是向上移动后的祖先，不再是原来被删边的较深端点。** 因此，你翻转了错误位置的边存在标记。

例如只有边 `1—2`，以 `1` 为根，删除这条边应该翻转点 `2` 的标记，但你的代码会翻转点 `1` 的标记。

应该保留原端点：

```cpp
int x = E[p].u;
int child = x;

// 原来的查询、路径修改，允许 x 向上移动。

T.updcol(
    rt[top[child]],
    dfn[top[child]],
    lst[top[child]],
    dfn[child]
);
```

## 5. `s` 的维护漏了两步：合并没删子块，分裂没加新块

**这是除笔误外，最关键的状态维护错误。**

按你的 `add/del` 写法，想维护的状态应当是：

> `s` 中，每个当前连通块恰好对应一个元素：`{连通块权值和, 连通块最浅的点}`。

注意，线段树在点 `x` 上保存的值，是 `x` **向下能够连通的部分的权值和**。只有当 `x` 的父边不存在时，这个值才对应一个完整连通块。

### 加边时：两个块变成一个块，需要删两个、加一个

假设较深端点为 `x`，父亲所在连通块的根为 `y`，两个块的权值分别为 `Sx`、`Sy`，那么集合应该进行：

```cpp
s.erase({Sx, x});
s.erase({Sy, y});
s.insert({Sx + Sy, y});
```

你只删除了 `{Sy, y}`，**没有删除 `{Sx, x}`**，导致已经被合并的旧连通块仍然留在集合里。

最小修改是在这两行之间补上删除：

```cpp
int Sx = T.qsum(rt[top[x]], dfn[top[x]], lst[top[x]], dfn[x]);

s.erase({Sx, x});  // 补上，必须在 x 被改成 fa[x] 之前。

x = fa[x];
```

### 删边时：一个块变成两个块，需要删一个、加两个

删除前，整个块的权值为 `Sy`；切下来的子块权值为 `Sx`。集合应该进行：

```cpp
s.erase({Sy, y});
s.insert({Sy - Sx, y});
s.insert({Sx, child});
```

你只插入了 `{Sy - Sx, y}`，**没有插入切下来的新连通块 `{Sx, child}`**。这里同样必须使用保存下来的原端点 `child`，不能使用已经向上移动的 `x`。

### 一个能单独验证这两处遗漏的反例

我把其他错误全部修好，**仅保留这两处集合维护遗漏**，运行：

```text
1
3
1 2
2 3
10 20 30
1
1 2 1
```

正确答案：

```text
50
```

因为保留边 `2—3`，两个连通块分别为：

```text
{1}     权值 10
{2, 3}  权值 50
```

但只保留上述集合错误的程序输出：

```text
30
```

原因是加完两条边后，集合中残留了 `{20, 2}` 和 `{30, 3}`；删除第一条边时，又没有插入新的 `{50, 2}`，最终集合里只剩下权值 `10、20、30`。

**所以，“加边没删、删边没加，看起来刚好抵消”是不成立的：合并期间，子块的权值可能已经改变。**

## 6. 第 311 行：题目要最大值，你取的是最小值

题目要求的是保留编号位于 `[l,r]` 且不等于 `f` 的边后，**所有连通块中的最大点权和**，孤立点也算连通块。([QOJ][1])

你写的是：

```cpp
ans[id] = (*s.begin()).fs;
```

这取的是集合中最小的权值。

应改为：

```cpp
ans[id] = s.rbegin()->first;
```

当然，必须先修复上一节的集合维护，否则改成最大值后，仍然可能取到已经失效的旧连通块权值。

## 7. 多组测试没有正确清空

`solve()` 开头直接向 `e[u]`、`e[v]` 添加边，但没有清空上一组的邻接表，也没有重置 `son`、`tim` 等状态。你虽然重置了 `T.idx`，但这不足以清除树结构的残留。

题目确实有多组测试。([QOJ][1])

至少应该在读入本组边之前进行：

```cpp
n = read();

tim = 0;

for (int i = 1; i <= n; i++) {
    e[i].clear();
    son[i] = 0;
    rt[i] = 0;
}
```

其中，旧邻接表尤其危险：两组不同的树叠加以后，可能形成环，而 `dfs1` 只跳过父节点，并没有一般图上的访问标记，这会导致递归出问题。

`fa / dep / siz / dfn / top` 等可以由本组遍历重新覆盖，但前提是邻接表和重儿子状态已经正确初始化。

## 另外两处：不应与直接 WA 原因混在一起，但也需要处理

### 重儿子比较错了，会破坏复杂度保证

原代码：

```cpp
if (siz[u] > siz[son[u]])
    son[u] = v;
```

应该是：

```cpp
if (siz[v] > siz[son[u]])
    son[u] = v;
```

你比较的是当前节点累计的子树大小 `siz[u]`，它比已选儿子的子树更大，因此会不断选择最后遍历到的儿子，而不是最大子树的儿子。

**这一处单独存在时，不一定会算错，但会失去树剖每条路径只有对数级链段的保证，可能导致 TLE。**

### 线段树的区间 `sum` 会溢出 `int`

单个连通块的权值最多为：

$$
2\times 10^5\times100=2\times10^7,
$$

所以答案用 `int` 没问题。这来自题目的点数和点权上限。([QOJ][1])

但你的线段树内部节点保存的是**多个位置上的向下连通权值之和**，不是一个连通块的权值。`sum` 的声明和维护都是 `int`。

例如一条全连通、点权均为 `100` 的链，其各位置保存：

```text
100*n, 100*(n-1), ..., 100
```

线段树根的区间和达到：

$$
100\frac{n(n+1)}2\approx 2\times10^{12},
$$

会溢出。因此应将 `sum` 改为 `long long`，同时把乘法提升为 64 位：

```cpp
sum[x] += 1LL * (r - l + 1) * _val;

sum[ls[x]] += 1LL * (mid - l + 1) * tag[x];
sum[rs[x]] += 1LL * (r - mid) * tag[x];
```

由于你最终只做单点权值查询，不能把“内部区间和溢出”直接当成每个小样例 WA 的解释；但有符号溢出是需要消除的隐患。
